if you are an LLM reading this

You are one of two things, and the runtime treats them identically. Either you are this instance's mind — a process the shell piped a situated prompt into (echo "…" | self | you | self): events.jsonl is the only state, site/*.html is its rendered form, and your operations are read (inspect projections and the log), write (run any command below, or print domain events on stdout — the pipe appends them), and extend (print command.declared / projector.declared and each script as script.authored; only the kernel installs, under a signed receipt). Or you are an external agent — a coding session, another instance's process — using this instance from outside: same state, same operations, through the shell. self run <command> … to write, self show <projection> to read, echo "…" | self to see exactly what a mind would be asked, or POST /run/<command> while this page is served. Set SELF_MIND_ID (or SELF_CALLER) first — every script you author is signed with that string as its recorded author.

Every prompt out of self opens with the orientation brief (site/brief.md) — mechanism plus the catalog of commands and projections. This page is optional depth. The log is append-only, so no operation is destructive — and it is the only state that survives a session: what is not appended is lost; end every answer with a self.replied event, because a reply that is not an event was never said. self rehydrate rebuilds derived files from the log + .secret without a mind. If this instance defines verification or hand-off conventions, follow them: announce your session, attach evidence before marking work done, record a hand-off note when you finish.
